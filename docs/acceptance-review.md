## 4. SDK 和资料核对

- 核对本机锁定 `wx-server-sdk@4.0.2` 的实际实现：`getWXContext` 独立读取运行时上下文，`ENV` 来自运行环境；数据库 `add` 返回 `_id`。
- 核对 `@cloudbase/node-sdk@3.18.3` 实际解析到的嵌套 `@cloudbase/database@1.4.3`。其生效事务入口为 `transaction/index.js`，支持 `collection().doc()`、回调返回值、提交和失败回滚。发布包同时留有旧 `transaction.js`，该残留文件不是当前导入入口。
- 根据生效的 `document.js` 核对事务 `set` 返回 `updated` 与 `upserted: [{_id}]`，据此实现写入确认；没有依靠未经验证的类型强转跳过结果校验。
- [DescribeTable 官方示例](https://cloud.tencent.com/document/product/876/127966)的索引 `Unique` 为布尔值，与当前管理 SDK 类型及解析一致；索引定义回读不替代真实唯一冲突测试。
- 依赖补丁及审计由[依赖审计记录](dependency-audit.md)单独维护。本文不把相关代码或测试通过当作依赖告警已全部解决。

## 5. 必须取得真实云证据的项目

以下项目不能用本地模拟验收完成：

1. **环境和部署：**有效 AppID 关联 dev 环境；六函数按同版产物部署；核实实际 Node 运行时和 `APP_ENV`。开发 health 返回真实环境与 requestId，生产 health 被拒绝。
2. **身份和登录：**从真实微信客户端调用，不能以控制台或传入 payload 代替可信 OpenID；同一账号重复 / 并发调用只产生一条持久化用户。
3. **唯一索引：**确认 `users.openid`、收藏和播放进度复合唯一索引就绪，并实际尝试重复键写入，验证平台拒绝第二条。
4. **默认拒绝：**真实客户端不能直接读取私有集合、修改 role / adminSchoolId / 审核状态 / 日志 / 配置，也不能未经授权操作云文件。
5. **初始化幂等：**在同一已确认开发环境重复执行初始化，第二次新增集合、索引和种子均为 0；原有用户、角色、配置和业务记录保留。
6. **首次超管：**目标用户先真实登录产生记录，再从服务端确认可信 OpenID 并受控执行脚本；验证角色和永久审计一起提交，重复授权和并发候选按规则处理。
7. **云端权限与状态：**普通用户管理请求拒绝；切换当前学校不改变 adminSchoolId；跨校、撤权、disabled / deleted 后下一次真实请求按规则拒绝。
8. **客户端联调：**真实登录响应进入正确引导页面，网络 / 权限错误可恢复；具体前端与模拟器结果见主测试记录。

真实验收执行路径：[数据库初始化与授权](database.md) → [安全规则](security-rules.md) → [云函数接口](cloud-functions.md)。取得证据前，相关云端项目保持待验，不标记为整个阶段 1 已完整验收。
