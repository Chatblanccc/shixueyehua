# 无云环境的本地完整体验

2026-09-16。用户希望在没有 AppID、CloudBase 环境时，也能完整操作已开发的功能。本地模式复用原生小程序页面和 service 接口，数据保存在本机独立存储，不调用云函数。

## 怎么体验

1. 启动开发版，点击“进入本地完整体验”。重开时会恢复体验状态。
2. 夜话首页有三期示例节目，可进入详情实际播放、暂停、拖动、前后切集、收藏；“我的”可查看收藏、历史，也可编辑资料和重新选班。
3. “我的 → 切换为管理员体验”，再进入管理中心。打开“发布夜话”，填写标题、主讲人，可直接使用内置示例音频，也可从微信文件选择 MP3/M4A；封面可选，范围支持全校或指定班级。
4. 保存草稿，进入音频管理，试听、编辑、发布；首页可看到新节目。下架后从听众列表消失，可编辑后重新发布。删除采用软删除。
5. “我的 → 重置体验数据”恢复初始示例资料、节目、收藏与进度。仅作用于本机，不修改云端。

这里的“完整”针对已实施业务：家书投稿/审核、班级管理、管理员管理和系统设置仍是后续 TASK，尚未开放。本机体验也不能证明平台锁屏后台播放或真实云上传已通过。

## 实现与验收边界

最终验收：2026-09-16，Node `22.23.2`（符合当前 engines，项目推荐版本仍见 `.nvmrc`）下 26 文件 / 325 项测试、lint、三套类型检查、构建、格式和六个云包独立检查通过。11:17:29（北京时间）微信模拟器 6 项流程再次通过，异常 0；报告位于 `artifacts/local-experience/verification.json`。

- `local-mode.ts`：dev + 无云 + 显式开关的选择条件。正式环境不读取本地服务作为失败回退。
- `local-repository.ts`：独立持久化、示例资料与组织、节目状态、个人进度/收藏；所有成功响应仍经正式 DTO 校验。本机存储失败会报告失败。
- `admin-audio.service.ts` 与两张管理页：文件选择、封面压缩、上传阶段反馈与取消、服务端校验/建档、草稿更新、状态过滤、试听、二次确认。
- 云上传以真实 PUT 传输、确认文件后绑定票据；传输期间显示阶段，不伪造百分比。失败/取消的票据进入既有清理链。真实云 PUT、元数据签名兼容、内容安全和清理仍需环境验收。
- `local-audio-manager.ts` 用本机文件播放来复用 PlayerController；页面切换仍保留播放实例。操作系统锁屏面板能力不属于这条本地播放路径。
- `assets/demo-night.m4a` 是内置合成语音夹具，24.252744 秒，说明文本已标注示例性质；不增加面向用户的音频生成能力。

自动化命令：`npm run verify`、`npm run format:check`、`npm run check:cloud`；微信本地体验检查 `npx tsx scripts/verify-local-experience.ts`。模拟器脚本自动应答发布/下架原生确认框，报告明确 `confirmationMocked=true`。测试结束恢复运行前的本地数据库，不把验收节目留在用户列表。

后续每个 TASK 必须同步提供可操作的本地路径，并记录本地体验与真实云端的各自结果。
