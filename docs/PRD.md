# 1. 产品概述

## 1.1 项目背景

学校需要一种比公众号文章更有温度、比开放论坛更可控的家校沟通载体。校长和学校管理者可以通过声音传递教育理念、校园故事、节日寄语和家校共育内容；学生、家长和教师则可以通过“一封家书”表达感谢、期待、成长感受与家庭教育思考。

产品不以海量图书、公开社交或商业变现为目标，而是围绕一所学校的真实使用场景，建立一个轻量、安静、可信的校园声音空间。

## 1.2 产品愿景

让学校的声音被认真听见，让家庭与学校之间的表达更真诚、更有仪式感。

## 1.3 产品定位

- **核心内容：**由校长或指定管理员上传和发布的原创校园音频。
- **核心互动：**普通用户投稿“一封家书”，经审核后以精选形式展示。
- **核心组织方式：**用户自主选择学校、年级和班级，系统保存当前班级身份。
- **核心运行方式：**个人主体、非商业、无支付、无广告、无开放式陌生人社交。

## 1.4 V0.1产品目标

1. 完成从微信进入、选择身份和班级，到收听校长音频的完整闭环。
2. 允许普通用户独立撰写并提交家书，管理员可审核、精选、驳回或隐藏。
3. 允许校长及指定管理员直接在小程序内上传、发布和管理音频。
4. 建立前端不可绕过的管理员权限、数据权限、内容审核与操作日志机制。
5. 在单校试点范围内稳定运行，同时避免把数据结构锁死为单校版本。

## 1.5 非目标

V0.1不追求成为“校园版喜马拉雅”，不建设公开内容生态，不提供用户上传音频、私信、评论区、关注关系、直播、付费、会员、广告、打赏、积分商城和学生排行榜。

## 1.6 关键产品决策

| 编号 | 决策 |
|---|---|
| D-01 | 音频内容的主要发布者是校长或指定管理员，普通用户不能上传音频。 |
| D-02 | 音频上传入口位于小程序内部管理中心，不要求独立电脑后台。 |
| D-03 | 原“家校论坛”改为“一封家书”，普通用户可以投稿文字和图片。 |
| D-04 | 家书默认进入审核队列，管理员审核后才能进入公开精选列表。 |
| D-05 | 用户可以自主选择班级；V0.1默认无需班主任审批。 |
| D-06 | 前端采用微信原生小程序，不采用跨平台框架；使用TypeScript与TDesign组件库。 |
| D-07 | 后端全部采用微信云开发，包括云函数、云数据库和云存储。 |
| D-08 | 产品按个人主体、非商业项目设计，并通过功能开关降低公开UGC的不确定性。 |

## 2.2 明确不做

- 名著阅读、国学、历史、科普等泛内容频道。
- 普通用户上传音频、视频或外部链接。
- 家书评论、回信、私信、用户关注、用户群组。
- 匿名投稿、公开显示学生真实姓名、公开用户主页。
- 音频付费、会员、广告、打赏、积分和排行榜。
- 独立Web管理后台、独立服务器、FastAPI、PostgreSQL、Redis。
- AI生成音频、AI自动封禁账号、复杂推荐算法。

## 2.3 后续预留但不在V0.1启用

- 班级口令或管理员审批入班。
- 家长绑定多个孩子、教师管理多个班级。
- 学校独立品牌、区域多校管理。
- 家书“写一封回信”。
- 小程序内直接录音并发布。
- 校园活动专题和定时发布。

# 3. 用户、身份与权限

## 3.1 身份与系统角色分离

“身份”描述用户在学校中的关系；“系统角色”决定后台权限。用户可以自选身份，但不能自设管理员角色。

| 类型 | 可选值 | 设置方式 |
|---|---|---|
| 用户身份 identity | student、parent、teacher | 用户首次进入时选择 |
| 系统角色 role | user、admin、super_admin | 只能由系统或超级管理员设置 |

## 3.2 角色说明

- **普通用户 user：**学生、家长和普通教师均可作为普通用户使用夜话与家书功能。
- **管理员 admin：**通常为校长或指定运营人员，只能管理被授权学校的数据。
- **超级管理员 super_admin：**项目最高权限，可创建学校、设置管理员和修改全局配置。

## 3.3 权限矩阵

| 功能 | 普通用户 | 管理员 | 超级管理员 |
|---|---:|---:|---:|
| 收听已发布音频 | 是 | 是 | 是 |
| 收藏和保存进度 | 是 | 是 | 是 |
| 投稿家书 | 是 | 是 | 是 |
| 查看自己的投稿状态 | 是 | 是 | 是 |
| 举报公开家书 | 是 | 是 | 是 |
| 上传、发布、下架音频 | 否 | 本校 | 全部 |
| 审核、隐藏家书 | 否 | 本校 | 全部 |
| 管理班级 | 否 | 本校 | 全部 |
| 设置普通管理员 | 否 | 否 | 是 |
| 修改系统模式 | 否 | 受限 | 是 |
| 查看管理操作日志 | 否 | 本校 | 全部 |

## 3.4 权限原则

1. 隐藏按钮不是权限控制；所有管理操作必须在云函数中再次核验OpenID、role和schoolId。
2. 管理员只能操作自己学校的数据，不允许通过修改请求参数跨校访问。
3. 超级管理员权限不能通过客户端参数获得，只能通过初始化脚本或已有超级管理员授予。
4. 普通用户对受保护集合不得直接写入，写操作通过云函数完成。
5. 音频、家书、举报和管理记录均采用软删除，保留必要操作轨迹。

管理员授权使用独立的 `users.adminSchoolId`：仅超级管理员或受控初始化脚本可设置；`currentSchoolId` 是用户可选择的使用上下文，不能用于授予管理权限。普通管理员必须同时满足 `role=admin` 和目标资源学校等于 `adminSchoolId`；缺少授权字段时拒绝管理。用户选班不改变授权，撤销管理员时清除授权字段。超级管理员跨校操作仍须验证目标学校和资源有效。

# 5. 核心业务规则

## 5.1 学校与班级规则

1. V0.1支持一个试点学校，但数据库所有业务数据均保留schoolId。
2. 用户首次进入必须选择身份、学校、年级和班级后才能进入主界面。
3. V0.1默认joinMode=free，用户选择后立即生效。
4. 用户可以在“班级”页面重新选择班级；切换行为写入日志。
5. 系统预留code和approval两种入班方式，但不作为V0.1发布阻断项。
6. 家书和音频的可见范围由当前学校与班级共同过滤。

## 5.2 音频规则

1. 普通用户不能创建、上传、修改或发布音频。
2. 管理员只能上传到自己学校，并选择全校可见或指定班级可见。
3. 仅status=published且未软删除的内容对普通用户可见。
4. 发布前必须具备标题、音频文件、主讲人、可见范围和封面；封面可使用系统默认图。
5. 音频文件上传成功但业务记录创建失败时，应进入临时文件清理流程。
6. 下架不删除历史记录，但用户不能继续从列表进入；已打开页面应提示内容已下架。
7. 播放完成判定建议为进度达到总时长的95%。

## 5.3 家书规则

1. 普通用户可以上传家书文字和0至3张图片，不能上传音频、视频和外部链接。
2. 家书支持保存草稿、提交审核、撤回和删除。
3. 默认模式为reviewed_showcase：提交后进入待审核，审核通过后进入精选列表。
4. 公开后的家书不支持直接修改；用户修改时应先撤回或产生新审核版本。
5. 驳回时管理员必须填写原因，用户可以修改后重新提交。
6. 家书公开展示时默认显示昵称和身份标签，不公开学生真实姓名、联系方式和详细家庭信息。
7. V0.1不提供评论、回信、点赞排行、关注和私信。

## 5.4 个人项目功能模式

系统配置letterPublishMode支持：

- **private：**家书仅作者与管理员可见。
- **reviewed_showcase：**管理员审核并精选后公开，V0.1默认值。
- **community：**审核通过后进入完整社区，仅预留，不在个人主体正式版本默认启用。

# 6. 核心业务流程

## 6.1 首次进入与选班

```text
启动小程序
  ↓
调用登录云函数，获取OpenID与用户记录
  ↓
无用户记录 → 创建基础用户
  ↓
未选择身份 → 选择学生/家长/教师
  ↓
未选择班级 → 选择学校、年级、班级
  ↓
保存currentSchoolId与currentClassId
  ↓
进入“夜话”首页
```

## 6.2 管理员发布音频

```text
管理员进入管理中心
  ↓
云函数验证role与schoolId
  ↓
选择微信可访问的音频文件，或使用后续录音能力
  ↓
上传音频与封面到云存储
  ↓
创建草稿并填写标题、主讲人、简介、可见范围
  ↓
管理员预览
  ↓
发布
  ↓
普通用户列表可见
```

## 6.3 用户收听

```text
进入夜话列表
  ↓
选择音频
  ↓
加载详情与历史进度
  ↓
播放并展示锁屏/后台播放信息
  ↓
暂停、切页、退出或定时同步进度
  ↓
达到95%标记完成
```

## 6.4 家书投稿与审核

```text
用户点击“写一封家书”
  ↓
填写标题、写给谁、正文和图片
  ↓
保存草稿或提交审核
  ↓
文本与图片安全检查
  ↓
进入pending队列
  ↓
管理员通过 / 驳回
  ↓
通过：进入精选列表
驳回：用户看到原因并可修改重提
```

## 6.5 举报与处置

```text
用户举报公开家书
  ↓
选择原因并提交
  ↓
生成report记录
  ↓
管理员查看原文与举报理由
  ↓
忽略 / 隐藏内容 / 处理用户
  ↓
记录处理人、结果与时间
```

# 7. 详细功能需求

## 7.1 登录、身份与初始化

| 编号 | 需求 | 验收标准 |
|---|---|---|
| AUTH-001 | 小程序启动时初始化云开发环境并调用登录接口。 | 能获取可信OpenID；客户端不传入或伪造OpenID。 |
| AUTH-002 | 首次登录自动创建users记录，默认role=user。 | 重复登录不重复创建；接口具备幂等性。 |
| AUTH-003 | 用户首次进入选择student、parent或teacher。 | 未选身份不能进入主页面；用户不能选择admin。 |
| AUTH-004 | 用户可填写昵称和头像，昵称缺失时使用系统默认昵称。 | 不依赖微信自动返回昵称头像才能完成流程。 |
| AUTH-005 | 本地保存轻量会话状态，关键用户信息每次从云端校验。 | 清除缓存后重新登录可恢复云端数据。 |
| AUTH-006 | 被disabled的用户不能投稿或执行管理操作。 | 登录后显示受限说明；仍可按配置查看公开内容。 |

## 7.2 学校、年级和班级

| 编号 | 需求 | 验收标准 |
|---|---|---|
| CLASS-001 | 首次进入依次选择学校、年级和班级。 | 选择项按schoolId与gradeId联动过滤。 |
| CLASS-002 | V0.1默认自由加入班级。 | 选择后立即更新currentClassId。 |
| CLASS-003 | “班级”页面展示当前学校、年级、班级和身份。 | 数据与users记录一致。 |
| CLASS-004 | 用户可重新选择班级。 | 切换成功后夜话和家书列表立即按新范围刷新。 |
| CLASS-005 | 系统记录班级成员关系和切换历史。 | class_memberships或日志中可追溯。 |
| CLASS-006 | 不允许用户选择disabled或graduated班级。 | 前端不展示，云函数也拒绝非法提交。 |

## 7.3 夜话首页与音频列表

| 编号 | 需求 | 验收标准 |
|---|---|---|
| AUDIO-001 | 首页展示当前学校可见且已发布的音频，按publishedAt倒序。 | 草稿、下架、删除或其他学校音频不出现。 |
| AUDIO-002 | 第一条内容可采用“本期夜话”大卡，其余为往期列表。 | 无内容时展示校园化空状态。 |
| AUDIO-003 | 列表卡片展示封面、标题、主讲人、日期和时长。 | 字段缺失时使用默认值，不出现布局错乱。 |

## 8.3 状态枚举

### 音频状态

- draft：草稿。
- published：已发布。
- offline：已下架。
- deleted：软删除。

### 家书状态

- draft：草稿。
- pending：待审核。
- approved：已通过并可按模式展示。
- rejected：未通过。
- hidden：管理员隐藏。
- deleted：软删除。

### 用户状态

- active：正常。
- disabled：限制投稿和管理操作。
- deleted：注销或软删除。

## 8.4 时间字段

- 统一使用服务端时间，不信任客户端时间。
- 所有业务记录至少包含createdAt和updatedAt。
- 审核、发布、下架和删除使用独立时间字段。
- 客户端展示时转换为本地时区和中文日期格式。

# 9. 技术架构与权限边界

## 9.1 技术基线

- 微信原生小程序、TypeScript、WXML、WXSS。
- TDesign Miniprogram作为基础组件库。
- 轻量全局状态：用户状态和播放器状态可使用MobX Miniprogram或项目内统一Store，避免散落在页面中。
- 微信云开发：云数据库、云存储、云函数、定时任务与日志。
- 不引入独立后端和独立Web后台。

## 9.2 架构图

```text
微信小程序
├─ 夜话 / 一封家书 / 班级 / 我的
├─ 管理员分包
├─ 用户与播放器Store
└─ wx.cloud调用层
       ↓
CloudBase云函数
├─ authApi
├─ classApi
├─ audioApi
├─ letterApi
├─ adminAudioApi
└─ adminApi
       ↓
云数据库 + 云存储 + 内容安全能力 + 日志
```

## 9.3 云函数划分

| 云函数 | 主要action |
|---|---|
| authApi | login、getProfile、updateProfile、requestDelete |
| classApi | listSchools、listGrades、listClasses、selectClass、getCurrentClass |
| audioApi | list、detail、saveProgress、history、toggleFavorite |
| letterApi | createDraft、updateDraft、submit、listPublic、detail、listMine、withdraw、delete、report |
| adminAudioApi | createDraft、publish、offline、delete、listManage |
| adminApi | reviewLetter、manageSchoolClass、grantAdmin、revokeAdmin、getConfig、setConfig、handleReport、listLogs |

采用领域聚合云函数，内部按action路由，减少大量重复依赖与鉴权代码。每个action仍然具有独立输入校验、权限检查和错误码。

## 9.4 存储路径建议

```text
/audio/{schoolId}/{year}/{uuid}.{ext}
/audio-cover/{schoolId}/{year}/{uuid}.{ext}
/letters/{openid}/{year}/{uuid}.{ext}
/defaults/audio-cover.png
/temp/{openid}/{uuid}.{ext}
```

## 9.5 数据访问边界

1. 客户端只允许读取必要的公开数据和本人数据。
2. users.role、审核状态、发布状态、管理日志不得由客户端直接修改。
3. 管理操作统一通过云函数；云函数从运行上下文获取OpenID。
4. 云函数根据数据库中的role和adminSchoolId校验管理员权限，再与资源schoolId比对，不采用客户端角色或用户自选学校作为授权。
5. 对上传文件采用路径隔离、类型与大小校验、上传后业务确认和临时文件清理。
6. 数据库与存储安全规则采用“默认拒绝、按需开放”。

初始默认拒绝规则随 TASK-102 创建集合时部署并验证；文件上传权限随业务最小化开放，在对应真实上传验收前完成 TASK-601。内容安全 TASK-600 是真实家书提交的前置要求，不能因为列在阶段6就推迟到业务完成后。

## 9.6 统一接口返回结构

```typescript
interface ApiResult<T> {
  success: boolean;
  data?: T;
  error?: {
    code: string;
    message: string;
    requestId?: string;
  };
}
```

客户端不直接展示底层异常堆栈；云函数日志保留requestId用于排查。

# 10. 非功能需求

## 10.1 性能

- 首页先展示骨架或缓存数据，再拉取最新列表。
- 列表使用分页，每页建议10至20条。
- 图片上传前压缩，列表使用缩略图。
- 播放进度不按秒写数据库，采用暂停、页面隐藏、切集和固定间隔批量同步。
- 管理分包不进入普通用户首包。
- 音频详情只在需要时获取临时访问地址。

## 10.2 稳定性

- 所有写接口具备输入校验、重复提交保护和明确错误码。
- 上传中断可重试，不创建半成品公开记录。
- 云函数失败时不让前端永久停留在加载状态。
- 关键状态变更写入管理日志。
- 删除操作优先软删除，提供误操作恢复空间。

## 10.3 兼容性

- 以当前微信开发者工具稳定版本和官方推荐基础库为基线。
- iOS与Android真机均需验证音频播放、后台播放、上传与图片预览。
- 不支持的倍速或文件选择能力应自动降级，而不是阻断播放。

## 10.4 可维护性

- TypeScript开启严格模式。
- 页面不得直接拼接云函数名称和错误文案，统一封装service层。
- 业务枚举集中定义，避免字符串散落。
- 云函数共享鉴权、校验、日志和错误处理模块。
- 每个模块必须包含README或代码注释说明数据流。

## 10.5 可用性

- 主操作按钮点击区域不小于常用移动端触控尺寸。
- 播放按钮、进度、审核状态和错误提示具有明确文字，不只依赖颜色。
- 表单自动保存草稿或提供离开提醒，避免长家书丢失。
- 空状态给出下一步操作，例如“暂无夜话，稍后再来”。

# 11. 内容安全、隐私与个人项目策略

## 11.1 内容安全

- 家书提交前进行文本和图片安全检查。
- 命中高风险内容时阻止提交或进入人工复核。
- 公开家书提供举报入口。
- 管理员可隐藏内容、限制用户和记录处置结果。
- 不使用“新账号前若干条抽查”规则，所有投稿执行统一审核流程。
- 自动审核只能提供风险提示，最终公开由管理员决定。

## 11.2 隐私最小化

V0.1只收集完成服务所必需的信息：OpenID、昵称、头像、身份、学校、年级、班级、收听记录、收藏、家书和管理操作记录。不收集精确位置、通讯录、身份证照片、人脸信息和家庭详细地址。

## 11.3 展示规则

- 前台显示昵称与身份标签，不显示OpenID。
- 学生真实姓名默认不公开。
- 家书中识别到手机号、微信号、详细住址等内容时，进入拦截或人工复核。
- 管理员页面仅展示审核所需信息。

## 11.4 个人项目上线策略

- 默认无支付、无广告、无商业内容分成。
- `letterPublishMode`默认使用reviewed_showcase。
- 若正式提审时公开UGC受限，可切换到private模式，而无需修改核心代码。
- 公开评论、私信、回信和用户关系全部保持关闭。
- 上线前根据当时微信小程序类目、备案与审核要求再次核对；此项属于发布准备，不改变V0.1技术架构。

# 13. 视觉与交互规范

## 13.1 设计关键词

温暖、安静、真诚、校园感、夜读感、有仪式感，不做儿童化卡通堆叠，也不做工具型后台风格。

## 13.2 建议视觉方向

- 主背景：米白、纸张暖色或低饱和夜色。
- 主色：深墨蓝或深褐色。
- 强调色：低饱和暖金或橙棕。
- 卡片：适度圆角和留白，避免密集边框。
- 家书详情可使用信纸纹理，但不得影响正文可读性。
- 音频封面保持统一比例和默认模板。

## 13.3 文案语气

- 夜话空状态：“今晚的夜话还在准备中。”
- 家书空状态：“还没有家书，写下第一封吧。”
- 审核中：“家书已送达，正在认真阅读。”
- 驳回：“这封家书暂未展示，请根据说明修改后再次提交。”
- 上传成功：“声音已保存，可以预览后发布。”

# 14. 验收方案

## 14.1 P0发布验收

- 普通用户不能通过页面、接口或修改参数上传和发布音频。
- 管理员可以在小程序中完成音频选择、上传、预览、发布、下架。
- 已发布音频可在前后台正常播放，进度可恢复。
- 用户可以选择和切换班级，列表范围随班级更新。
- 用户可以保存、提交、撤回和查看家书状态。
- 所有公开家书都经过管理员审核。
- 管理员可通过、驳回、隐藏家书并填写原因。
- 跨校数据隔离有效。
- 管理操作有日志，关键写接口有错误码。
- iOS和Android真机均完成核心流程测试。

## 14.2 核心验收场景

| 场景 | 操作 | 预期结果 |
|---|---|---|
| 新用户首次进入 | 登录、选身份、选班级 | 成功进入夜话，用户记录唯一 |
| 普通用户越权 | 直接调用发布音频action | 返回FORBIDDEN，不产生记录 |
| 管理员发布音频 | 上传、预览、发布 | 普通用户列表出现，信息正确 |
| 音频续播 | 播放至中途退出再进入 | 从保存进度继续 |
| 家书投稿 | 保存草稿、提交 | 状态从draft变pending |
| 家书驳回 | 管理员填写原因驳回 | 用户看到原因并可重提 |
| 家书通过 | 管理员通过 | 在精选列表按范围可见 |
| 班级切换 | 切换到另一个班级 | 页面数据刷新且日志可追溯 |
| 举报处理 | 用户举报，管理员隐藏 | 内容停止公开，报告已处理 |
| 内容下架 | 管理员下架正在播放的内容 | 新进入不可播放，已有页收到提示 |

## 14.3 Definition of Done

每项功能只有同时满足“代码完成、权限校验、错误状态、日志、测试、真机验证、文档更新”才算完成。

# 15. 发布与运行配置

## 15.1 环境

建议至少保留开发环境和正式环境；条件允许时增加测试环境。环境ID通过配置文件和构建环境区分，不在业务代码中硬编码。

## 15.2 初始数据

正式首次启动前至少准备：

- 1所学校。
- 对应年级和班级。
- 1个超级管理员。
- 1个校长管理员。
- 2至3条测试音频。
- 默认音频封面。
- 默认系统配置。

## 15.3 发布开关

| 开关 | 默认值 |
|---|---|
| letterPublishMode | reviewed_showcase |
| enableLetterImages | true |
| maxLetterImages | 3 |
| enableClassApproval | false |
| enableComments | false |
| enablePrivateMessage | false |
| enablePayment | false |
| maintenanceMode | false |

## 15.4 回滚原则

- 页面功能通过配置开关关闭，而不是紧急删除数据。
- 音频和家书使用下架或隐藏，避免物理删除。
- 数据结构升级提供兼容字段和迁移脚本。
- 发布前导出关键配置和管理员列表。

# 16. 风险、假设与待确认事项

| 风险或事项 | 当前处理方案 |
|---|---|
| 个人主体公开UGC审核存在不确定性 | 默认审核后精选；保留private模式开关 |
| 手机端选择音频文件能力受微信入口限制 | 支持选择微信可访问文件；后续增加直接录音 |
| 音频文件造成存储和流量增长 | 限制格式和大小，监控云开发资源用量 |
| 普通用户绕过前端上传文件 | 发布权限始终由云函数控制；加强存储规则和临时文件清理 |
| 用户随意选择错误班级 | V0.1接受自由选择；预留口令与审批模式 |
| 管理员误操作 | 软删除、二次确认、管理日志 |
| 内容审核误判 | 安全检测仅作前置，公开由管理员最终确认 |
| 多校扩展导致越权 | 所有业务集合带schoolId，管理员权限绑定学校 |

待确认但不阻塞开发的内容：学校正式名称、首批年级与班级、默认封面、校长展示名称、音频单文件上限、家书是否显示班级名称。

# 17. 附录

## 17.1 术语

- **夜话：**由校长或管理员发布的校园音频。
- **家书：**普通用户投稿的文字与图片内容。
- **精选：**管理员审核通过并允许公开展示的家书。
- **当前班级：**用户当前使用的学校、年级和班级上下文。
- **管理员：**具有音频发布和家书审核能力的本校账号。
- **超级管理员：**具有跨学校配置和授权能力的最高角色。

## 17.2 建议错误码

| 错误码 | 含义 |
|---|---|
| UNAUTHORIZED | 未登录或登录态失效 |
| FORBIDDEN | 无权限执行该操作 |
| USER_DISABLED | 用户已被限制 |
| INVALID_ARGUMENT | 参数格式或业务规则不合法 |
| SCHOOL_SCOPE_DENIED | 跨学校访问被拒绝 |
| CLASS_NOT_AVAILABLE | 班级不可选择 |
| AUDIO_NOT_FOUND | 音频不存在或已下架 |
| UPLOAD_FAILED | 文件上传失败 |
| CONTENT_REJECTED | 内容安全检查未通过 |
| LETTER_STATE_CONFLICT | 家书当前状态不允许该操作 |
| DUPLICATE_REQUEST | 重复提交 |
| RATE_LIMITED | 操作过于频繁 |
| INTERNAL_ERROR | 系统内部错误 |
