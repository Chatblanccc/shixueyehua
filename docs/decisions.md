将开发规则移至根目录 `AGENTS.md`，Markdown 基线移至 `docs/`，原始 Word 留在原目录，不维护第二套同名 Markdown。产品和验收以 PRD 为准，TASK 与实施细节以任务书为准。

## DEC-002 管理授权与当前班级分离

原 User 类型缺少授权学校字段，却要求管理员只能管理本校。新增 `adminSchoolId?: string` 表示 V0.1 单校管理员授权范围，仅超级管理员或受控初始化脚本可写。

- `currentSchoolId` / `currentGradeId` / `currentClassId` 由合法选班流程更新，仅表示当前使用上下文。
- `admin` 必须有有效 `adminSchoolId`，且目标资源的 `schoolId` 与其一致；缺失授权字段时拒绝管理操作。
- `super_admin` 可跨校管理，仍须检查目标学校、资源存在及状态；不得由客户端声明角色。
- 授予 admin 写入授权学校；撤销时清除该字段。选班和修改个人资料都不能改授权。
- users 的管理范围索引统一为 `role + adminSchoolId`。

验收覆盖普通用户越权、跨校资源、自选学校不提权和撤权后立即失效。V0.1 不增加多校管理员授权关系表。

## DEC-004 配置存储与读取约定

原 PRD 的 `key/value/schoolId` 描述存储记录，任务书的 `SystemConfig` 描述业务读取结果，二者分层使用：

- 每个作用域一条 `system_configs` 记录，`key='app'`；全局 `_id='app:global'`，学校 `_id='app:school:<schoolId>'`，学校 ID 使用系统生成的 ID。
- 记录保留 `schoolId`（全局无此值）、`value`、`createdAt`、`updatedAt`、`updatedBy`；配置字段放入 `value`。全局存完整默认值，学校记录存合法覆盖值。
- 按“代码默认值 → 全局值 → 已校验的学校覆盖值”读取；服务端校验字段、类型及角色白名单后才允许写入。阶段 1 只初始化全局配置，学校设置界面及完整写入权限在 TASK-503 落实。
- `enableLetterImages=true` 纳入类型与默认种子；false 时有效图片上限为 0，否则为 `maxLetterImages`，V0.1 上限为 3。
- `enableComments`、`enablePrivateMessage`、`enablePayment` 始终为 false；`community` 仅保留类型，不开放启用入口。
- 家书默认模式仍为 `reviewed_showcase`，但公开查询无法取得有效配置或安全服务不可用时不得放行未核验内容，应返回可重试状态并保留草稿。

TASK-100 已定义存储类型与读取类型；TASK-102 种子引用同一 `DEFAULT_SYSTEM_CONFIG`，已通过确定性 ID 幂等写入与保留既有配置的本地测试，真实云端尚未运行。

## DEC-005 登录与首次超管授权的顺序

TASK-103 在阶段 2 页面尚未开发时，返回 / 派生明确的 onboarding 步骤，使用有效占位页面承接，避免跳不存在的路由或循环跳转。阶段 1 不宣称完成身份与选班业务。

TASK-102 交付超管脚本及测试；真实授权顺序为：目标账号在开发环境首次登录 → 在服务端确认 users 记录与可信 OpenID → 在受控运维上下文运行脚本 → 验证权限和日志。用户不存在时脚本拒绝，不凭测试 OpenID 造真实管理员，不提供客户端 bootstrap action。默认拒绝对非开发环境运行，后续生产初始化另按发布流程配置。

任务书曾列出 `public` 枚举，但 PRD 的首期发布范围仅全校或指定班级。V0.1 使用 `school | classes`，不开放跨校公开音频。旧稿中的 `public` 不构成新增需求。

## DEC-007 Node 基线更新

旧稿使用 Node.js 20 LTS。2026-09-15 核验时，Node 官方已将 20 列为 EOL，24 与 22 列为 LTS；CloudBase 官方运行时表列有 24.11、22.21 和 20.19。新工程默认采用 Node 24 LTS，具体云函数 runtime 标识必须在 TASK-003 对照目标环境锁定；若目标环境不支持，核验仍受支持的 Node 22 LTS 作为回退，不新部署 Node 20。

初始系统探测为 Node 22.23.2 / npm 10.9.8；工程现以 `.nvmrc` 锁定 Node **24.21.0**，阶段 1 历史验收在该版本下通过（13 个文件共 124 项测试：后端与数据库 96、客户端 21、SDK 兼容 7）；第二阶段当前结果见 [stage-2.md](stage-2.md)。根 engines 保留 `^22.13.0 || ^24.0.0` 的兼容范围，不修改系统 Node 路径作为工程依赖。本地版本、CloudBase 支持表和实际部署结果分别记录。

云函数构建语法目标暂用 `node22` 兼容子集，不代表已经选定或部署 Node 22 云环境。首次真实部署仍优先核验 Node 24 LTS，六个函数须使用同一实际支持的 runtime。

来源：[Node.js 版本状态](https://nodejs.org/en/about/previous-releases)、[CloudBase 运行时支持](https://docs.cloudbase.net/cloud-function/runtime-support)。依赖精确版本见[技术栈](TECH_STACK.md)和三个独立依赖清单的锁文件。

## DEC-008 无云环境时的本地开发边界

当前微信工具查询返回 `ret=-601059：测试号不能使用云服务`。用户已明确暂无正式 AppID，先完成本地开发；本轮继续推进源码、页面结构、类型、可控测试和构建，不再把取得云环境作为这部分工作的前提。

- `SHIXUE_ENV=dev` 且未配置环境 ID 时，生成明确的页面预览模式，不调用云函数、不虚构用户或业务数据；正式云请求失败不回退到预览成功。
- test/prod 构建缺环境 ID 直接失败；数据库与首位超管脚本默认 dry-run，apply 只允许明确匹配本地配置的 dev 环境。
- 登录代码仍从微信可信上下文取身份。当前页面能预览不代表微信登录通过，也不代表数据库安全规则已部署。
- 模拟器自动化、真实云端与真机证据分别记录；阶段 1 历史的本地 124 项测试不能替代这些验收。2026-09-15 22:59:55（北京时间）完整模拟器的启动、四 Tab、七个管理页共 12 项检查通过，异常数为 0；真实云端与手机尚未验收，详见[测试记录](test-cases.md)。

## DEC-009 依赖与可复现构建

- TypeScript 固定为 **5.9.3**，适配当前 `typescript-eslint@8.70.0` / ESLint 工具链；strict 设置保持启用。版本升级须同时验证解析器支持及所有类型检查。
- 根清单管理开发工具；`miniprogram/package.json` 管理 TDesign / MobX；`config/cloud-runtime/package.json` 声明精确的 `wx-server-sdk@4.0.2` 和生产兼容包归档，并携带定向补丁 overrides。三个清单分别保留锁文件。
- `shared/` 的纯逻辑单向打包到小程序 `generated/`，不把服务端 SDK 带入客户端；六个云函数各自包含共享源码、独立运行清单、锁文件及 `vendor/shixue-lodash-set-safe-1.0.1.tgz`。归档源于 `vendor/lodash-set-safe/`，是独立安装所需制品，不可在部署时遗漏。
- `check:cloud` 核对六个实际 dist 包的运行清单、锁与 vendor 一致性，再在仓库外按锁安装、审计运行依赖并加载六入口；本轮通过，未调用真实云接口。
- 根生产、云运行依赖及小程序审计当前为 0；含开发依赖的根审计仍有 17 个 moderate，high / critical 为 0。补丁已进行实际 SDK、本机传输和独立安装兼容回归；没有强制降级官方 SDK。剩余告警与真实云端兼容边界见[依赖审计](dependency-audit.md)，部署前仍须重新核验。

## DEC-010 原生路由完成后再执行会话重定向

模拟器实测发现，在管理页进入路由尚未完成时立即 `reLaunch`，可能打断原生路由完成信号，表现为画面已回启动页、导航回调仍等待且实际页面栈未同步。修复等待原生路由完成后，回调和实际栈均恢复；页面缓存、生命周期 Promise 或固定延时不作为修复依据。

- `App.onLaunch` 注册 `wx.onBeforeAppRoute` / `wx.onAppRouteDone`；`RouteTransition` 记录进行中的事件，`SessionNavigator` 在任何异步等待前串行排队，避免两个守卫同时发起导航。
- 优先按非空 `routeEventId` 精确配对。本地基础库 3.17.3 实测 `reLaunch` 的 before 有 ID、done 为空，但路径、openType、webviewId 一致；空完成 ID 只回退匹配这三个字段的唯一候选，有歧义则继续等待。
- 等待超时向调用方报错并提示重新打开小程序，不清空未完成路由而提前放行。六项路由事件回归和三项导航队列回归通过。
- 最低基础库要求 **3.5.5**。旧版即使存在 `onAppRouteDone`，参数也可能不同，不能只检查函数是否存在；正式 AppID 就绪后须在平台配置最低版本。当前项目 `libVersion: 3.17.3` 仅表示本地工具验证版本。
- 全部七个管理页的完整模拟器检查已通过：等待真实原生导航回调，检查实际栈已回启动页且 user 为空，再实际点击进入页面预览。页面守卫不代替服务端角色与学校范围鉴权。

接口契约参考项目已安装的官方 `miniprogram-api-typings@5.2.3` 与[页面路由监听](https://developers.weixin.qq.com/miniprogram/dev/framework/app-service/route-event-listener.html)；本地空 ID 行为以[测试记录](test-cases.md)中的实际证据为准。

## DEC-011 验收入口与减少无谓重编译

`npm run verify:stage1` 依次串联质量检查、格式检查、独立云包检查、两项数据库 dry-run、根及小程序生产审计、完整模拟器检查。本轮各子命令已分别实际通过；聚合命令新增后没有再整套重复运行，不把它表述为额外一次验收。

`prepare:local` 和 `build:shared` 对内容相同的生成文件不重写，减少微信工具自动重编译。模拟器验证前冻结源码与构建产物，运行中不写小程序文件；仅文档改动只做文档检查。已有通过证据且无新变化、失败或未解决问题时，不重复启动工具或重跑模拟器。

## DEC-012 第二阶段资料、组织与事务边界

- 用户已将正式 AppID 与云环境延期，阶段 2 的本地开发继续。真实云端待验不会被本地替身结果替代。
- 可选头像采用内置 `avatarPreset: moon/book/bamboo`，避免未经文件归属和存储规则验证的任意 fileId 写入。自定义图片上传与内容检查仍需后续实现，当前没有声称可上传头像。
- 目录接口将原任务表的数组细化为 `CursorPage<T>`，每页 20、上限 100，三级页面可继续加载；游标只定位已验证父级中的位置，不作为访问授权。
- 自由选班事务更新 users.current*、upsert user/class 成员并写 class_switch 日志，任何失败不形成部分成功。保留其他历史成员；修改身份同步当前有效成员，历史其他成员保留加入时身份。
- 用户切班不修改管理员授权学校。前端每次管理页 onLoad/onShow 和操作前取新权限，后台旧请求不能充当回前台后的校验；权限错误立即清页面内容并退出。
- 资料草稿按账号保存在本次内存中，返回 / 重开表单可恢复；预览不创建用户。当前班级缓存按账号与范围版本失效，四 Tab 进入时刷新。音频和家书真实列表仍由阶段 3 / 4 接入，不把刷新信号当作内容业务完成。

实现和验证见[第二阶段记录](stage-2.md)。
