# 产品介绍

> 本文是《[V0.1 产品需求文档](PRD.md)》的阅读入口，便于团队理解产品。详细业务规则和验收仍以 PRD 及 [开发任务书](CODEX_TASKS.md) 为准。

## 1. 实学夜话是什么

实学夜话是一款校园音频与“一封家书”微信小程序。校长或指定管理员发布校园声音，学生、家长和教师收听夜话、保存收听进度，也可以提交文字和图片家书，由管理员审核后精选展示。

产品按个人主体、非商业项目设计，首期面向一所学校试点，数据结构预留多学校隔离能力。具体试点学校、人员和运营数据尚未确认，开发种子数据不代表真实学校已接入。

产品希望让学校的声音被认真听见，让家庭与学校之间的表达更真诚、更有仪式感。视觉与文案强调温暖、安静、校园感和清楚易读。

## 2. 为谁提供什么价值

用户自行选择的“身份”与系统授予的“角色”相互独立。选择教师身份不会获得管理权限。

| 使用者 | 常见场景 | 产品提供的价值 |
|---|---|---|
| 学生，`identity=student` | 收听校园故事、寄语；写给家人、老师或未来的自己 | 找到与当前学校和班级相关的内容，保留有仪式感的表达 |
| 家长，`identity=parent` | 收听教育理念；向孩子或学校写家书 | 在日常时间中了解学校，通过可保存的文字表达期待与感受 |
| 教师，`identity=teacher` | 收听学校内容；投稿家书 | 参与校园文化表达，按普通用户规则使用产品 |
| 管理员，`role=admin` | 在手机上上传音频、预览发布；审核和处理本校家书 | 在小程序管理中心完成内容运营，操作有记录可追溯 |
| 超级管理员，`role=super_admin` | 初始化学校、授予或撤销管理员、管理全局配置 | 建立并维护学校范围与权限边界 |

普通用户角色为 `user`。只有 `admin`、`super_admin` 可以上传和发布音频；管理员的每次操作都必须在服务端验证角色及其学校授权范围。

## 3. 信息架构

| 主导航 | 用户主要操作 |
|---|---|
| 夜话 | 浏览本期与往期音频、播放、继续收听、控制迷你播放器 |
| 一封家书 | 阅读精选家书、进入投稿、查看正文与图片、举报公开内容 |
| 班级 | 查看当前学校、年级、班级和身份，重新选择班级 |
| 我的 | 查看个人信息、收藏、收听历史、我的家书；有权限时进入管理中心 |

管理中心位于小程序管理员分包，包含音频发布与管理、家书审核、班级管理、管理员管理和系统设置。管理员管理仅向超级管理员开放。

## 4. 核心使用流程

### 首次进入

微信进入 → 云函数确认身份并创建或恢复用户 → 选择学生/家长/教师身份 → 选择学校、年级、班级 → 进入夜话。

V0.1 采用自由选班，无需班主任审批。服务端验证学校、年级、班级的有效性和层级关系；切换班级后，内容范围随之刷新并保留切换记录。

### 校园音频

管理员进入管理中心 → 选择微信可访问的音频文件 → 上传音频及封面 → 保存草稿、填写主讲人和可见范围 → 预览 → 发布 → 对应学校或班级用户收听。

用户可播放、暂停、调整进度、切换上下期、收藏和续播。后台与锁屏播放须经真机验证；倍速按平台实际能力启用。草稿、下架或软删除的音频不得出现在普通用户可访问的新请求中。

### 一封家书

用户写标题、收信对象、正文及 0～3 张图片 → 保存草稿或提交 → 文本和图片内容安全检查 → 待审核 → 管理员通过或填写原因驳回 → 按模式与可见范围展示。

- 草稿和被驳回内容可以继续编辑，待审核内容可撤回。
- 已通过内容不能直接覆盖修改；修改必须重新进入审核流程。
- 作者在“我的家书”查看状态与驳回原因。
- 公开内容可举报，管理员可隐藏和处理，保留必要审计记录。
- 内容安全服务失败时不得绕过检查直接公开；默认阻止公开提交并保留草稿。

## 5. V0.1 功能范围

| 模块 | 本版本交付范围 | 任务映射 |
|---|---|---|
| 工程和基础能力 | 原生小程序工程、共享类型、接口封装、鉴权、数据库初始化、会话 | TASK-001～003、TASK-100～103 |
| 身份和班级 | 身份选择、学校年级班级联动、自由选班与切换、管理员守卫 | TASK-200～202 |
| 夜话 | 可见范围查询、列表详情、全局播放、进度历史收藏、管理员上传与发布管理 | TASK-300～305 |
| 家书 | 草稿、图片投稿、内容检查、我的家书、审核、精选展示、举报处置 | TASK-400～405、TASK-600 |
| 管理中心 | 本校管理、学校年级班级管理、管理员授权、配置开关、日志与审核通知 | TASK-500～504 |
| 安全和交付 | 数据库与存储规则、异常体验、自动化验证、真机测试与发布清单 | TASK-601～604 |

以上是规划范围，不代表功能已实现。任务状态见 [实施计划](implementation-plan.md)，开发先后与里程碑见 [功能规划](ROADMAP.md)。

### 家书展示模式

| 模式 | 行为 | V0.1 定位 |
|---|---|---|
| `reviewed_showcase` | 所有投稿经内容安全检查和管理员审核，按学校与可见范围精选展示 | 默认模式 |
| `private` | 仅作者与有权限管理员可见，公开列表不返回家书 | 可用的保守运行模式 |
| `community` | 更完整的社区展示模式 | 仅预留，本轮及 V0.1 不启用 |

“公开”指经过审核且处于允许展示范围内，不代表跨学校或向互联网所有访客开放。对用户只展示必要的昵称和身份信息，不公开 OpenID、学生真实姓名、联系方式或详细家庭信息。

### 明确不做

V0.1 不提供普通用户上传音频、视频或外部链接，不增加评论、回信、私信、关注、公开用户主页、排行榜、支付、会员、广告、打赏、积分商城或独立 Web 管理后台，也不建设泛内容频道、AI 音频生成及复杂推荐系统。

班级口令或审批、多孩子/多班级关系、区域多校运营、直接录音、活动专题及定时发布仅作后续讨论，不纳入本轮开发准备和 V0.1 交付承诺。后续功能仍须单独确认范围。

## 6. 如何评价产品是否可用

### 交付验收

以真实闭环和权限验证为依据：登录选班 → 管理员发布夜话 → 用户收听并恢复进度 → 用户提交家书 → 管理员审核 → 按范围精选展示。补测跨校访问、普通用户越权、重复提交、管理员撤权、内容安全失败、下架隐藏和弱网场景。

自动化检查通过、云端联调通过、iOS/Android 真机通过、提交平台审核、平台审核通过应分别记录。页面原型、固定数据或模拟返回不能作为业务完成证据。

### 试点观察

依据 PRD 记录首次进入完成情况、音频播放启动成功与收听进度、家书草稿/提交/审核情况、审核积压、主要错误及存储流量。先收集可核验的试点数据，再确定改进目标；当前不设未经确认的用户规模、活跃率或成功率数字。

这些数据用于改善流程和运行质量，不公开形成学生排名。学校正式名称、首批班级、主讲人展示名、默认封面、音频文件上限和家书班级名称展示方式，列为上线前逐项确认的配置事项。
